# Contributing

This project lives or dies by one habit: **claims are checkable, and ideas are stress-tested before they're trusted.** If you keep that, you're welcome here.

## The three ground rules

1. **Cite primary sources.** Every factual claim needs a link to a primary source — the actual WHO / World Bank / UN / IPCC / peer-reviewed paper / official dataset, not a news article *about* it where possible. Quote the relevant number or sentence inline. If a number isn't published anywhere credible, write "not published" — never invent or estimate-and-present-as-fact.
2. **Steelman before you strike.** When you criticize a solution, first state the strongest version of the argument *for* it. When you propose a solution, write its own strongest objection. A proposal with no honest "Objections" section is incomplete.
3. **Roots, not symptoms.** Keep asking "and why does that happen?" Push each problem toward a cause we can actually act on.

## How to add or change things

### Fix or add a fact
- Find the relevant `problems/NN-*/README.md`.
- Edit the **Key facts** or **Sources** section. Keep the source link and the year.
- Corrections (a number was wrong, a source is outdated) are just as valuable as new facts — maybe more.

### Improve a solution
- Add a sharper **objection**, or a **revised version** that survives an existing objection.
- Note the trade-offs plainly. Every real solution costs something; say what.

### Propose a new problem area
- Open `problems/` and copy the structure of an existing folder.
- A new problem should be (a) large in human impact, (b) at least partly addressable, and (c) not already covered by an existing folder. Say which.

### Propose a solution
- Add it under `proposals/` with its own folder.
- Use the same discipline as `proposals/political-system/`: idea stated fairly → honest case for it → strongest objections → improved/alternative versions → what we'd measure to know if it worked.

## The problem-folder template

Every `problems/NN-*/README.md` follows the same shape so the repo stays navigable:

1. **Scope** — what's in, what's out.
2. **Key facts** — sourced numbers, most load-bearing first.
3. **Root causes** — the "why," pushed as deep as the evidence allows.
4. **Connections** — how this problem feeds and is fed by the others.
5. **Candidate solutions** — each with its trade-offs and objections.
6. **Metrics we'd watch** — how we'd know things are getting better or worse.
7. **Open questions** — what we genuinely don't know yet.
8. **Sources** — links, with years.

## Tone

Direct, specific, unsentimental. The goal is not to feel righteous; it's to be right and to help. If something here is wrong, say so plainly — that's a contribution, not an attack.
